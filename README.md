# Yakut-Simulator

Общая основа двух одиночных VR-сценариев на Unreal Engine 5.8.3. Реализованы главное меню, независимый захват каждой рукой, физическое отпускание и бросок предметов, использование и базовые классы операций. Обучение и пошаговые задания по умолчанию не запускаются.

Карты «Рыболовный траулер» и «Кабинет терапевта» пока содержат тестовую площадку взаимодействий. Рыболовные механизмы, обработка рыбы, пациенты и обследования ещё не реализованы.

## Сборка и запуск

```powershell
& 'M:/UE/UE_5.8/Engine/Build/BatchFiles/Build.bat' YakutSimulatorEditor Win64 DebugGame '-Project=M:/Prototypes/Yakut-Simulator/YakutSimulator.uproject' -WaitMutex -NoHotReloadFromIDE
```

Запуск редактора без шлема:

```powershell
& 'M:/UE/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Win64-DebugGame.exe' 'M:/Prototypes/Yakut-Simulator/YakutSimulator.uproject' -nohmd
```

Открытие `YakutSimulator.uproject` двойным щелчком запускает Development-редактор. Он использует отдельную DLL проекта, которую сборка DebugGame не обновляет. После изменений исходников для такого запуска также соберите Development:

```powershell
& 'M:/UE/UE_5.8/Engine/Build/BatchFiles/Build.bat' YakutSimulatorEditor Win64 Development '-Project=M:/Prototypes/Yakut-Simulator/YakutSimulator.uproject' -WaitMutex -NoHotReloadFromIDE
```

Начальная карта — `/Game/Prototype/Maps/L_MainMenu`. Нажмите Play и выберите карту в меню. Из рабочей сцены меню позволяет продолжить, открыть другую карту или вернуться на начальную карту.

## Управление

| Действие | VR | Клавиатура и мышь |
| --- | --- | --- |
| Взять правой рукой | Удерживать правый Grip | Удерживать E |
| Взять левой рукой | Удерживать левый Grip | Удерживать Q |
| Отпустить или бросить | Отпустить Grip; скорость задаётся движением руки | Отпустить E или Q |
| Использовать правой рукой | Правый Trigger | ЛКМ |
| Использовать левой рукой | Левый Trigger | F |
| Переместиться | Левый стик вперёд, выбрать место, вернуть стик | WASD |
| Повернуться | Правый стик в сторону | Удерживать ПКМ и двигать мышь |
| Меню | Y; на Index — левая B | Tab; Esc в самостоятельной игре |
| Отмена | Правая B | Backspace |

В PIE клавиша Esc может завершать игровой сеанс средствами редактора, поэтому для меню используйте Tab. На Vive Wand нажатие левого тачпада включает выбор точки телепортации, отпускание подтверждает переход; меню открывается левой Menu-кнопкой.

Предмет выбирается по близости к руке. Один предмет может находиться только в одной руке. Использование базового предмета включает световой индикатор до отпускания Trigger. Blueprint-наследник может переопределить ReceiveUseStarted и ReceiveUseEnded. UInteractionZoneComponent доступен для размещения предметов; обязательной последовательности действий нет.

## Архитектура

`AVirtualRealityPawn` обрабатывает ввод и трекинг. `AWorkItem` управляет предметом, захватом и использованием. `UInteractionZoneComponent` проверяет размещение. `UWorkOperationComponent` хранит состояние операции. `AScenarioDirector` связывает операции и зависимости шагов. `WBP_MainMenu`, `WBP_MapEntry` и `WBP_ScenarioPanel` наследуются от стандартного `UUserWidget`. Вёрстка и обработчики находятся в UMG Blueprint; собственных C++-классов виджетов нет.

- `Source/YakutSimulator/Public` и `Private` — исходники общей базы.
- `Content/Prototype/Input` — Input Actions и общий Input Mapping Context.
- `Content/Prototype/Maps` — главное меню и две тестовые карты.
- `APrototypeGameMode.ScenarioMaps` — список карт меню. Новую карту также нужно включить в Packaging Settings.
- `Scripts/CreatePrototypeAssets.py` — создание ассетов через Unreal API. Существующие карты не заменяет; раскладку IMC пересоздаёт.

Дальнейшая проработка существующих карт не входит в текущую задачу. Настройки карт сохраняются. Начальная карта и список карт для cook заданы в Config.

## Проверка взаимодействий

Автоматизированные проверки `YakutSimulator.Runtime.ItemInteraction.Fishing` и `.Clinic` самостоятельно открывают соответствующую карту и запускают desktop PIE. Они вводят настоящие Input Actions и проверяют обе руки, использование, разделение UI и инструмента, отпускание, скорость броска и жизненный цикл операции. Созданные проверкой предметы временные и не сохраняются в карту. После проверки PIE завершается и открывается карта главного меню.

## Meta XR Simulator без шлема

На этом компьютере установлен Meta XR Simulator 76 с прямым вводом клавиатуры и мыши. Он использует OpenXR и не требует изменения VPN. Версия 207.1 также установлена, но её отдельная панель управления требует локального IPv6-соединения, которое здесь блокируется.

1. Закройте редактор этого проекта.
2. Запустите `StartMetaXR.cmd` из корня проекта.
3. Выберите VR Preview в Unreal Editor.
4. Управляйте устройствами во встроенном окне Meta XR Simulator. В Inputs должна быть надпись `Keyboard + Mouse are Connected`. Полная раскладка находится в Inputs > View Binding Details.

| Клавиши симулятора | Действие |
| --- | --- |
| `[` и `]` | Выбор головы, левого или правого контроллера |
| W, A, S, D | Перемещение выбранного устройства |
| R, F | Перемещение вверх и вниз |
| Стрелки | Поворот выбранного устройства |
| Q, E | Наклон влево и вправо |
| U | Grip выбранного контроллера |
| T | Trigger выбранного контроллера |
| N | Y/B выбранного контроллера |

Скрипт задаёт `XR_RUNTIME_JSON` и `META_XRSIM_CONFIG_JSON` только для дочерних процессов. Системный OpenXR runtime не изменяется. Конфигурация версии 76 использует `use_legacy_input=true`.

Локальные установки: `M:/Tools/MetaXR/Legacy76`, `M:/Tools/MetaXR/Configuration/tools/xrsim` и `M:/Tools/MetaXR/Cli/metavr.exe`.

Историческая проверка старого шаблона подтверждала запуск VR Preview, трекинг головы и контроллеров и открытие меню. Она не подтверждает поведение нового C++-прототипа. Результаты новых проверок учитываются отдельно.

Документация: [Meta XR Simulator](https://developers.meta.com/vr/documentation/unreal/xrsim-intro/).

## Явные связи между объектами

Ввод задаётся именованными свойствами AVirtualRealityPawn: InteractionMapping, GrabLeftAction, GrabRightAction, UseLeftAction, UseRightAction и остальные действия. Их значения по умолчанию назначены в конструкторе; обработчики и автотесты используют непосредственно эти свойства. Индексного массива действий и загрузки по вычисляемым именам больше нет.

MainMenuClass и ScenarioPanelClass задаются в контроллере. MainMenuMap задаётся в игровом режиме и по умолчанию берётся из GameDefaultMap. Панель читает конкретного директора из свойства ScenarioDirector владеющего контроллера, установленного до CreateWidget. Несколько настроенных директоров считаются неоднозначной конфигурацией.

ValidateSteps проверяет уникальность идентификаторов, отдельные операции, существование зависимостей и отсутствие циклов. Предметы, созданные после BeginPlay, регистрируются автоматически. При пересечении нескольких зон размещения выбирается ближайшая подходящая зона.

Проверка до переноса UI, 2026-11-09: сборки DebugGame и Development успешны; два расширенных автотеста на DebugGame прошли. Проверены обратный порядок шагов, позднее создание предмета, передача директора панели, ближайшая зона и переходы через меню. Функция создания mapping проверена на временных объектах без сохранения ассетов. Физический шлем и packaged runtime в этот прогон не входили. Свидетельства находятся в Saved/Verification/InputAudit.

Меню создаёт WBP_MapEntry для каждой записи ScenarioMaps. Каждая кнопка хранит собственный FScenarioMapEntry и передаёт soft-ссылку карты в OpenScenarioMap. Ошибки меню обновляются по OnMenuErrorChanged, панель — по OnScenarioChanged. Tick для обновления текста не используется. Scripts/CreatePrototypeUI.py пересобирает только три UI-ассета и не изменяет карты; перед повторной генерацией сохраняйте резервные копии этих пакетов.
