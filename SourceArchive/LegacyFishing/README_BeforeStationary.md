# Yakut-Simulator

Общая основа двух одиночных VR-сценариев на Unreal Engine 5.8.3. Реализованы главное меню, независимый захват каждой рукой, физическое отпускание и бросок предметов, использование и базовые классы операций. Обучение и пошаговые задания по умолчанию не запускаются.

На карте «Рыболовный траулер» реализован производственный цикл: поиск косяка сонаром, выпуск трала, буксировка, подъём и выгрузка улова, сортировка по видам, заточка ножа, обработка, упаковка и заморозка. Судно движется горизонтально, без качки и наклонов. Карта «Кабинет терапевта» остаётся площадкой общей базы взаимодействий; пациенты и обследования пока не реализованы.

## Управление

| Действие | VR | Клавиатура и мышь |
| --- | --- | --- |
| Взять правой рукой | Удерживать правый Grip | Удерживать E |
| Взять левой рукой | Удерживать левый Grip | Удерживать Q |
| Отпустить или бросить | Отпустить Grip; скорость задаётся движением руки | Отпустить E или Q |
| Использовать правой рукой | Правый Trigger | ЛКМ |
| Использовать левой рукой | Левый Trigger | F |
| Переместиться | Левый стик вперёд, выбрать место, вернуть стик | WASD |
| Повернуться | Правый стик в сторону | Удерживать ПКМ и двигать мышь |
| Отмена | Правая B | Backspace |


Предмет выбирается по близости к руке. Один предмет может находиться только в одной руке. Использование базового предмета включает световой индикатор до отпускания Trigger. Blueprint-наследник может переопределить ReceiveUseStarted и ReceiveUseEnded. UInteractionZoneComponent доступен для размещения предметов; обязательной последовательности действий нет.

## Архитектура

Каждый из 25 проектных нативных UCLASS имеет BP-наследника. C++ реализует механику, Blueprint задаёт её настройки и используемые ассеты. Рабочие карты используют эти BP; тестовые C++-фикстуры могут создавать нативные классы напрямую.

| Где настраивать | Что задаётся |
| --- | --- |
| BP_PrototypeGameMode | Классы BP игрока и контроллера, список карт меню |
| BP_VirtualRealityPawn | Именованные Input Actions, контекст ввода, параметры игрока |
| BP_PrototypePlayerController | Класс UMG главного меню |
| BP_TrawlerVessel | Движение судна, коллизия и визуальные компоненты корпуса, палубы, рубки и рамы |
| BP_Trawl | Класс создаваемой рыбы, ёмкость сети, длина троса и глубина лова |
| BP_FishingWinch, BP_FishingSonar | Скорость лебёдки, дальность поиска и модели оборудования |
| BP_FishSortingConveyor, BP_FishProcessingBench, BP_FishFreezer, BP_KnifeSharpeningStation | Модели станций, зоны приёма и параметры обработки |
| BP_KnifeItem, BP_FishItem, BP_FishContainerItem | Модели, физические параметры, параметры инструмента и тары |
| BP_FishingScenario | Этапы и операции, параметры консоли и корпус дисплея |

Основные BP находятся в Content/Prototype/Blueprints и Content/Fishing/Blueprints. Для шести органов управления созданы отдельные наследники рычага. Косяки и конвейеры трески и пикши также имеют отдельные BP с назначенным видом. DA_Cod и DA_Haddock используют класс BP_FishSpeciesDefinition. Связи между конкретными экземплярами оборудования и их расположение задаются на карте.

BP_InteractionZoneComponent, BP_WorkOperationComponent и BP_VesselMovementComponent назначены вместо нативных компонентов через Component Class Overrides в BP владельцев. Их настройки видны в панели Components владельца; владельцы сохраняют собственные размеры зон и количество требуемой продукции.

Scripts/ConfigureProjectBlueprints.py создаёт отсутствующие классы и задаёт первоначальные настройки; существующие настройки сохраняются. Генераторы сцен получают классы через этот каталог. Для изменения скорости, модели, действий ввода или класса рыбы откройте соответствующий Blueprint и измените Class Defaults либо компонент. Все пользовательские виджеты остаются UMG Widget Blueprint.

`AWorkItem` удерживает физическое тело через `UPhysicsHandleComponent`: коллизии продолжают работать, предмет не прикрепляется к руке. Цель захвата ограничивается sweep коллизии предмета до положения руки. При отпускании передаются линейная и угловая скорости руки в мировых координатах.

`APhysicalLever` наследует этот захват, но его тело соединено с основанием через `UPhysicsConstraintComponent`. Шарнир разрешает поворот до 40 градусов в обе стороны; после отпускания привод удерживает выбранный угол. `Value` находится в диапазоне от -1 до 1 и передаётся через `OnValueChanged`.

## Рыболовный сценарий

Все рычаги управляются захватом и движением руки. Положительное отклонение оранжевого рычага трала выпускает трос, отрицательное поднимает сеть; нейтраль останавливает лебёдку. Отдельный жёлтый рычаг выгружает улов после остановки судна и полного подъёма сети. Синий рычаг включает конвейеры. Кнопки на промысловой консоли сканируют акваторию и переключают обнаруженные цели; в VR используется указатель и Trigger, на ПК — направление взгляда и ЛКМ при пустой руке.

Сонар показывает вид, расстояние, относительный пеленг и глубину реального косяка. Выбор цели не телепортирует судно и не создаёт рыбу. Трал ловит при движении судна быстрее 40 см/с, выпуске не менее 8 м троса и пересечении области косяка. Ёмкость сети — шесть рыб, запас косяков уменьшается на фактический улов. В текущей сцене доступны треска и пикша. Для окончания смены нужно обработать и заморозить три рыбы.

После выгрузки свободные физические рыбы лежат на палубе. Отпустите каждую над соответствующим сортировочным конвейером. На рабочий стол принимается отсортированная рыба. Для заточки удерживайте нож, зажмите Trigger и проведите лезвием по камню; для обработки таким же образом проведите лезвием через область разделки лежащей на столе рыбы. Неподвижный нож не завершает действие. Обработанную рыбу отпустите в синий ящик, затем перенесите ящик в открытый морозильник. Во время заморозки ящик заблокирован; после завершения его можно забрать. Упакованная рыба остаётся внутри ящика.

Лебёдка и конвейеры поддерживают состояние неисправности через SetFaulted. Для восстановления верните соответствующий рычаг в нейтраль и используйте Trigger. Случайные поломки в текущей сцене не включены.

Сеть следует за судном к вычисляемой позиции; тросы отображаются отрезками. Симуляции ткани, натяжения каната, качки и гидродинамики нет. Разделка определяется контактом и движением инструмента и меняет состояние продукта; геометрическое разрезание меша не реализовано. Заморозка занимает три секунды. Это упрощённые игровые механики.

Классы рыболовного сценария находятся в Source/YakutSimulator: AFishingScenario связывает операции и результаты, AFishingSonar и AFishSchool отвечают за поиск и запас рыбы, AFishingWinch и ATrawl — за сеть, AFishItem и AFishContainerItem — за продукцию, AFishSortingConveyor, AFishProcessingBench, AKnifeSharpeningStation, AKnifeItem и AFishFreezer — за обработку. Роли оборудования задаются именованными ссылками. Промысловая консоль — WBP_FishingConsole, наследник стандартного UUserWidget с логикой в Blueprint.

## Визуал и исходники моделей

В SourceAssets/Fishing/Concepts сохранены два сгенерированных концепта и точные промпты. Они служат референсами и не являются игровыми скриншотами. В SourceAssets/Fishing/Models находятся Blender-исходник, OBJ-модели и описание материалов. Созданы корпус, палуба, рубка, кормовая рама, лебёдка, сеть, два вида рыбы, нож, точильный камень, конвейер, стол, ящик, морозильник и консоль. Вода использует MI_CalmOcean с родительским материалом Water Plugin /Water/Materials/WaterSurface/Water_Material_CustomMesh.

Scripts/ModelFishingAssets.py запускается в Blender и экспортирует модели. В редакторе Scripts/ImportFishingAssets.py импортирует геометрию и настраивает коллизии; Scripts/UpgradeFishingScene.py заменяет оборудование L_Fishing и связывает его; Scripts/CreateFishingConsole.py создаёт UMG; Scripts/RefineFishingLighting.py настраивает небо и экспозицию. Сборка сцены заменяет существующее оборудование, поэтому её не следует запускать для обычного открытия карты. Перед повторной генерацией сохраняйте отдельную копию изменённых пакетов. Первоначальные резервные копии находятся в Saved/Backups/FishingScenario.

Палуба имеет простую выпуклую коллизию. Она переносит свободные тела через физический контакт. Вода не блокирует предметы. Визуальные части корпуса и закреплённое оборудование прикреплены к судну с Mobility=Movable.

## Проверка взаимодействий

Автоматизированные проверки `YakutSimulator.Runtime.ItemInteraction.Fishing` и `.Clinic` самостоятельно открывают соответствующую карту и запускают desktop PIE. Они вводят настоящие Input Actions и проверяют обе руки, использование, разделение UI и инструмента, отпускание, скорость броска и жизненный цикл операции. Созданные проверкой предметы временные и не сохраняются в карту. После проверки PIE завершается и открывается карта главного меню.

## Meta XR Simulator без шлема

На этом компьютере установлен Meta XR Simulator 76 с прямым вводом клавиатуры и мыши. Он использует OpenXR и не требует изменения VPN. Версия 207.1 также установлена, но её отдельная панель управления требует локального IPv6-соединения, которое здесь блокируется.

1. Закройте редактор этого проекта.
2. Запустите `StartMetaXR.cmd` из корня проекта.
3. Выберите VR Preview в Unreal Editor.
4. Управляйте устройствами во встроенном окне Meta XR Simulator. В Inputs должна быть надпись `Keyboard + Mouse are Connected`. Полная раскладка находится в Inputs > View Binding Details.

| Клавиши симулятора | Действие |
| --- | --- |
| `[` и `]` | Выбор головы, левого или правого контроллера |
| W, A, S, D | Перемещение выбранного устройства |
| R, F | Перемещение вверх и вниз |
| Стрелки | Поворот выбранного устройства |
| Q, E | Наклон влево и вправо |
| U | Grip выбранного контроллера |
| T | Trigger выбранного контроллера |
| N | Y/B выбранного контроллера |

Скрипт задаёт `XR_RUNTIME_JSON` и `META_XRSIM_CONFIG_JSON` только для дочерних процессов. Системный OpenXR runtime не изменяется. Конфигурация версии 76 использует `use_legacy_input=true`.

Локальные установки: `M:/Tools/MetaXR/Legacy76`, `M:/Tools/MetaXR/Configuration/tools/xrsim` и `M:/Tools/MetaXR/Cli/metavr.exe`.


Документация: [Meta XR Simulator](https://developers.meta.com/vr/documentation/unreal/xrsim-intro/).

## Явные связи между объектами

Ввод задаётся именованными свойствами AVirtualRealityPawn: InteractionMapping, GrabLeftAction, GrabRightAction, UseLeftAction, UseRightAction и остальные действия. Ассеты назначены в BP_VirtualRealityPawn; обработчики и автотесты используют непосредственно эти свойства. Индексного массива действий и загрузки по вычисляемым именам больше нет.


ValidateSteps проверяет уникальность идентификаторов, отдельные операции, существование зависимостей и отсутствие циклов. Предметы, созданные после BeginPlay, регистрируются автоматически. При пересечении нескольких зон размещения выбирается ближайшая подходящая зона.
