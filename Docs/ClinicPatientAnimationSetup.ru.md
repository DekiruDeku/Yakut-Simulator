# Подключение анимаций пациента

Дата: 15 ноября 2026 года. По новому указанию пользователя техническое подключение выполнено через Unreal MCP, без computer use. Продолжен уже созданный пользователем `/Game/Minigames/Clinic/Blueprints/ABP_ClinicPatient`: собран AnimGraph, назначен Body, заполнены пять Pose Definitions и этапы пяти обследований. Реакции на прикосновения отложены.

В проекте нет клинических анимаций и Anim Montage. Сейчас все пять поз используют совместимый `AS_UE5_MF_Idle` как временную анимацию; Transition Montage оставлены пустыми. Открывание рта, показ руки и подготовка к осмотру ещё не анимированы. Поворот спиной задан через Yaw Offset. Для замены клипов достаточно настроек из раздела 4; стандартный вызов монтажа уже реализован в C++.

## 1. Создать AnimBP

Используется существующий `/Game/Minigames/Clinic/Blueprints/ABP_ClinicPatient` для скелета текущего пациента `SKEL_UE5_F`. Его родитель — **ClinicPatientAnimInstance**. При создании нового AnimBP для другой модели этот класс можно выбрать при создании либо через **File → Reparent Blueprint**.

У класса уже есть:

- `PoseAnimation` — Animation Sequence для удержания запрошенной позы.
- `PoseState` — идентификаторы приёма и запроса, имя позы и фаза `Idle / Transitioning / Ready / Failed`.
- `HasPoseAnimation` — проверка наличия удерживаемой анимации.
- `ReceivePoseRequested` — событие запроса позы. По умолчанию оно реализовано в C++: запускает назначенный монтаж и обрабатывает завершение/прерывание.

В EventGraph ничего подключать для стандартного пути не требуется. Владелец пациента — Actor; получение Pawn через Try Get Pawn Owner здесь не подходит. Нативный AnimInstance получает пациента через Get Owning Actor.

## 2. Собрать AnimGraph

Соберите цепочку:

```text
PoseAnimation → Sequence Player (Loop Animation = true) ── True Pose ┐
Local Space Ref Pose ────────────────────────────────── False Pose ├─ Blend Poses by Bool
HasPoseAnimation ──────────────────────────────────── Active Value ┘
    → Slot «DefaultSlot» → Output Pose
```

В Sequence Player выведите свойство **Sequence** входным пином и соедините с Get PoseAnimation. Это динамический плеер; конкретный клип выбирает код из настроек позы. Нулевой клип обрабатывается веткой Ref Pose. При наличии анимации используется True Pose.

Slot разместите **после** базовой позы и смешивания, чтобы монтаж мог управлять всем телом. У используемых монтажей должен быть тот же Slot, обычно **DefaultGroup.DefaultSlot**. Если выбран другой Slot, используйте его согласованно в AnimGraph и во всех монтажах.

В Class Defaults AnimBP установите **Root Motion Mode → Ignore Root Motion**. Положение и поворот актора контролирует AClinicPatient. Используйте клипы на месте: перемещение корневой кости не должно дублировать программный поворот.

Compile и Save. Удерживаемые клипы разных поз переключаются через PoseAnimation; для полноценного движения между позами назначается Transition Montage. В этой версии нет отдельной таблицы монтажей для каждой пары исходной/целевой позы: стандартный монтаж выбирается по целевой позе.

## 3. Назначить AnimBP пациенту

В `BP_ClinicPatient` выберите Body:

- Animation Mode → **Use Animation Blueprint**.
- Anim Class → **ABP_ClinicPatient**.

Сохраните BP. Проверьте Body у уже размещённого пациента в L_Clinic: отдельное переопределение Anim Class на экземпляре может перекрывать BP. Не меняйте Transform зон и сокетов ради подключения анимации.

## 4. Заполнить Pose Definitions

В Class Defaults `BP_ClinicPatient → Clinic → Animation → Pose Definitions` уже заданы:

| Pose Identifier | Назначение | Yaw Offset | Transition Seconds |
| --- | --- | --- | --- |
| `Idle` | Исходное ожидание / возврат после обследования | 0 | 1,0 |
| `ChestFront` | Обследование груди | 0 | 0,35 |
| `ChestBack` | Обследование спины | 180 | 1,0 |
| `Mouth` | Термометр / открытый рот | 0 | 0,35 |
| `Hand` | Пульсоксиметр и показ предплечья | 0 | 0,35 |

Для каждой записи:

- **Loop Animation** — Animation Sequence удерживаемой позы. ChestFront и ChestBack могут использовать один клип, поскольку актор поворачивается целиком.
- **Transition Montage** — конечный монтаж подготовки к этой позе. Не используйте в нём бесконечно зацикленные секции: готовность ожидает завершения монтажа.
- **Transition Seconds** — длительность плавного поворота актора и минимальное время подготовки. Для поворота подберите значение под длительность монтажного движения; для остальных поз можно начать с 0,35 с.

Yaw Offset отсчитывается от исходного поворота экземпляра. Измерение разрешается после окончания вращения и монтажа. Начальная поза задаётся в `DA_Case_* → Начальная поза`. Если поле пустое, используется `Default Pose Identifier` из `Class Defaults → Clinic → Animation` Blueprint пациента. Исходное значение — `Idle`. При заполненном `Pose Definitions` выбранная поза должна быть в этом списке.

Loop Animation и Transition Montage можно временно оставить пустыми: сохраняется техническая опорная поза, а готовность наступает после Transition Seconds. Если клипы назначены, требуется AnimInstance указанного нативного класса; несовместимый скелет или неуспешный запуск монтажа дают Failed.

## 5. Настроить этапы действий

В Data Assets действий поле **«Этапы обследования»** (`PresentationStages`) задаёт единственную последовательность поз и зон. Отдельного массива Areas у действия больше нет: `GetAreas()` объединяет зоны этапов автоматически. `PoseDefinitions` остаётся в BP пациента; граф AnimBP не нужно менять для обследования из уже настроенных поз.

| Data Asset | Этапы обследования: Pose Identifier → Areas |
| --- | --- |
| `DA_Action_AuscultateChest` | `ChestFront → LeftChest, RightChest`; затем `ChestBack → LeftBack, RightBack` |
| `DA_Action_MeasureTemperature` | `Mouth → Mouth` |
| `DA_Action_MeasurePulseAndOxygen` | `Hand → LeftFinger` |
| `DA_Action_MeasureBloodPressure` | `Hand → LeftUpperArm` |
| `DA_Action_InspectInjury` | `Hand → LeftForearm` |

У ReadTriageCard, вопросов и направлений оставьте этапы пустыми. Вопросы и направления сохраняют текущую позу. Повтор активного инструментального запроса не запускает подготовку заново. Новое обследование отменяет предыдущую незавершённую попытку.

Пока пациент готовится, хайлайты скрыты и приборы не накапливают время. После Ready подсвечивается только активная группа. Обе передние зоны обследованы → запрашивается ChestBack. После прохождения всех групп пациент возвращается к исходной позе. Завершение всего приёма остаётся отдельной командой игрока и доступно во время подготовки.

Для нового обследования добавьте этап, задайте Pose Identifier из Pose Definitions пациента и перечислите его Areas. Каждый этап требует позу и хотя бы одну область; зоны не должны повторяться внутри этапа или между этапами. Для единой группы без смены позы используйте один этап с нужной исходной позой, например Idle. Прежний жёстко заданный мгновенный поворот по имени зоны удалён; для разделения груди/спины используются два этапа.

Пустые этапы означают действие без областей, например ReadTriageCard. Для обследования с включённым «Требуется прибор» (`bUsesInstrument`) хотя бы один этап обязателен. Связь конкретного прибора с действием задаётся в его BP через ActionDefinition. Физические Zone/Highlight и их калибровка в Areas пациента сохраняются отдельно.

## 6. Когда потребуется свой обработчик

Для стандартного запуска монтажей оставьте ReceivePoseRequested без переопределения. Его реализация выполняет Montage Play и использует делегат конца монтажа, а не Delay.

Если переопределяете ReceivePoseRequested в AnimBP, выберите один путь: вызов Parent для стандартного поведения либо полностью собственное воспроизведение. Во втором случае сохраняйте **Request.VisitIdentifier** и **Request.RequestIdentifier** вместе с конкретной попыткой и вызывайте **CompletePoseRequest** с ними:

- монтаж завершился → `Completed`;
- монтаж прерван → `Interrupted`;
- подготовка не удалась → `Failed`.

Передавайте в callback сохранённые идентификаторы его запроса. Смена обследования или приёма и завершение приёма аннулируют старый запрос. Стандартная отмена останавливает монтаж перехода, запущенный стандартным обработчиком. Если AnimBP управляет воспроизведением самостоятельно, он отвечает и за остановку своих монтажей. Уведомления AnimNotify можно использовать для эффектов. Готовность подтверждается после достижения нужной позы.

`AClinicPatient.GetPoseState()` и `OnPatientPoseChanged` предназначены для чтения состояния. Периодический OnScenarioChanged не запускает монтажи. В AnimBP не размещаются правила диагноза и выдачи медицинских результатов.

## Проверки

Обе конфигурации редактора были собраны на этапе C++-архитектуры с седьмым тестом `YakutSimulator.Clinic.PatientPresentation`; исходники при подключении Editor не менялись. Тест содержит проверки разбиения зон, запрета контакта до готовности, повторного запроса, выбора группы и устаревшего завершения, но не запускался.

Через MCP подтверждены компиляция AnimBP и BP пациента без предупреждений, сохранение шести изменённых ассетов, семь узлов и шесть связей AnimGraph, Ignore Root Motion, разбиение зон четырёх действий и наличие начальных поз для шести случаев. После повторной загрузки L_Clinic экземпляр наследует Anim Class и Pose Definitions из BP; отдельные переопределения карты не добавлялись. Все локальные Transform, Box Extent и настройки подсветок совпали с исходными. Файлы карты, Skeleton и Skeletal Mesh побайтно не изменились. Исходные пакеты и сохранённый пользовательский AnimBP зарезервированы в `Saved/Backups/Clinic/BeforeAnimationSetup-20261115`; отчёты находятся в `Saved/Verification/Clinic/AnimationSetup`.

PIE, Automation, физический контакт и воспроизведение монтажей не проверялись. Специальные клипы и монтажи ещё нужно добавить и назначить.

После подключения проверяйте положение зон в каждой используемой позе, соответствие Slot и скелета, переход спереди назад, смену обследования и отмену приёма во время монтажа. Игровые прогоны агентом требуют отдельного разрешения согласно ProjectRules.md.
