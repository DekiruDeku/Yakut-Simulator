# Рыболовная смена: сборка уровня в Unreal Engine 5.8

Реализован одиночный PCVR-прототип: защита и проверка остановки → постановка трала → траление → выборка → переход в цех → сортировка → переход к столу → обработка → сдача улова → результаты и повтор.

Вся игровая логика находится в C++. Level Blueprint и графы тиков создавать не нужно. Используется существующий `BP_XRPawn` проекта; его исходные графы не изменены.

## 1. Сборка и запуск

1. Закройте Unreal Editor перед полной сборкой новых C++ классов.
2. Откройте PowerShell в корне репозитория и выполните:

   ```powershell
   & 'C:\Program Files\Epic Games\UE_5.8\Engine\Build\BatchFiles\Build.bat' YakutSimulatorEditor Win64 Development "-Project=$PWD\YakutSimulator\YakutSimulator.uproject" -WaitMutex -NoHotReloadFromIDE -NoUBA
   ```

3. Запустите проект:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Start-YakutSimulator.ps1
   ```

   Скрипт запускает установленный Unreal Editor 5.8 напрямую, без зависимости от ассоциации `.uproject` в Windows. Он включает MCP на `http://127.0.0.1:8000/mcp`. Готовая карта `/Game/Fishing/Maps/L_FishingPrototype` уже входит в проект и назначена стартовой картой редактора и игры. Другой редактор, уже занимающий порт 8000, следует закрыть штатно.

При повторении сбоя запуска сначала смотрите конец `YakutSimulator/Saved/Logs/YakutSimulator.log`. Исходники, `Content` и автосохранения удалять не требуется. Перед этой реализацией сделана копия исходников и настроек в `YakutSimulator/Saved/FishingPrototype/BackupBeforeFishing`.

Модуль MetaXR `OculusXRTelemetry` требует MSVC 14.50 или новее. Для игровой цели Win64 в `YakutSimulator.Target.cs` выбран Visual Studio Build Tools 2026 и новейший установленный стабильный MSVC. На этом ПК уже был установлен MSVC 14.51, поэтому переустановка не понадобилась. Для других машин подходит [установка MSVC средствами Microsoft](https://learn.microsoft.com/en-us/cpp/overview/acquire-msvc). Рыболовная карта добавлена в `MapsToCook` в `DefaultGame.ini`. Сборка игрового бинарника не заменяет упаковку контента: для отдельного дистрибутива используйте Package Project.

### Открытие в Rider

1. В Rider откройте `YakutSimulator/YakutSimulator.uproject` внутри репозитория. Генерировать `.sln` для этого не требуется.
2. В **Settings → Build, Execution, Deployment → Toolset and Build → .NET CLI executable path** должен быть выбран встроенный в UE .NET 10:

   ```text
   C:\Program Files\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\DotNet\10.0\win-x64\dotnet.exe
   ```

   На этом ПК путь уже сохранён в локальном `YakutSimulator.uproject.DotSettings.user`. Этот файл и `.idea` исключены из Git: на другой машине путь задаётся по её установке UE. Использование системного .NET 9 приводило к ошибке запуска UnrealBuildTool `Microsoft.NETCore.App 10.0.0 was not found`.
3. Выберите конфигурацию **Development Editor | Win64** и цель **YakutSimulator**. Обычная полная сборка выполняется при закрытом Unreal Editor.

В `.uproject` явно включены `EnhancedInput` и редакторский `RiderSourceCodeAccess`. Предлагаемый Rider плагин RiderLink нужен для дополнительных функций IDE и не является условием открытия или сборки проекта.

### Meta XR Simulator

На этом ПК 07.11.2026 подтверждён отказ клавиатуры и мыши в runtime 207.1: сброс настроек, восстановление MSI и проверка фокуса окон ввод не вернули. В отдельном запуске с официальным runtime 69 пользователь подтвердил работу ввода; Unreal получил изменившиеся позы головы и контроллеров.

Команда ниже проверена через Windows PowerShell 5.1: первый запуск загрузил и проверил пакет, повторный запустил runtime 1.69.0 из кэша. Проверены восстановление окружения вызывающего процесса, сохранение системного runtime и блокировка повторного запуска редактора. Локальный отчёт: `YakutSimulator/Saved/MetaXRInputRepair/launcher-validation.json`.

1. Штатно закройте Unreal Editor этого проекта.
2. В корне репозитория выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Start-YakutSimulator.ps1 -Simulator
   ```

3. При первом запуске скрипт загружает [официальный пакет Meta 69.0.0](https://npm.developer.oculus.com/com.meta.xr.simulator/69.0.0), проверяет SHA-512 и распаковывает его в `YakutSimulator/Saved/MetaXRSimulator/69`. Загрузка — около 172 МБ. После очистки этой папки скрипт загрузит пакет заново.
4. В Unreal выберите **Play → VR Preview**. В заголовке окна игры будет **Meta XR Simulator (1.69.0)**.
5. В тёмном окне Meta XR Simulator закройте начальные диалоги, самостоятельно выбрав настройки статистики, если такой запрос появится. Кликните по изображению игры. `WASD` перемещают голову, стрелки поворачивают вид, ПКМ с движением мыши меняет направление взгляда. Остальные назначения доступны через **Inputs → View Binding Details**.

Это обход отказа ввода в 207.1, а не исправление её бинарного кода. Редактор наследует переменные runtime от скрипта, который сразу восстанавливает своё окружение; пользовательские и системные настройки Windows не меняются. В этом режиме используется стандартный OpenXR Unreal, а плагин `OculusXR` отключается параметром запуска: Meta SDK 207 требует `xrShareSpacesMETA`, отсутствующую в runtime 69. Функции Meta SDK, например пространственные якоря и passthrough, в этом режиме недоступны. Рыболовный прототип использует стандартные компоненты OpenXR. Обычный запуск без `-Simulator` использует настройки `.uproject` и системный OpenXR runtime.

## 2. Быстрое создание готового тестового уровня

Готовая карта уже сохранена в проекте. Следующие шаги нужны только для создания карты в копии проекта, в которой её ещё нет.

1. После сборки и запуска откройте **Tools → Debug → Output Log**.
2. В строке ввода выберите режим **Python**.
3. Выполните:

   ```python
   exec(open(r'C:\Users\dev\Documents\Unreal Projects\Yakut-Simulator\YakutSimulator\Scripts\BuildFishingLevel.py', encoding='utf-8').read())
   ```

4. Дождитесь сообщения `FISHING_LEVEL_READY`.
5. Откроется `/Game/Fishing/Maps/L_FishingPrototype` с палубой, отдельным нижним цехом, VR GameMode, стартом игрока, 14 станциями, светом и подвижным макетом трала.
6. Сохраните карту и выберите **Play → VR Preview** при подключённом шлеме и работающем OpenXR runtime.

Скрипт сохраняет текущий уровень перед переключением и отказывается перезаписывать уже существующую карту. Для дальнейшей работы редактируйте созданный уровень. Повторно выполнять генератор для той же карты не нужно.

Это проверочная сцена из примитивов. Её можно заменить корабельным окружением, сохранив акторы логики и их привязки.

В `/Game/Fishing/UI/` входят шрифт `F_FishingCyrillic` и его материал `MI_FishingText`: они нужны для русских надписей Text Render. Если эти сгенерированные ассеты отсутствуют, выполните в обычном режиме ввода **Cmd** команду `Fishing.PrepareTextAssets`, перезапустите редактор, затем повторите создание карты. Команда проверяет наличие кириллицы и создаёт недостающие ассеты, не заменяя существующие.

## 3. Сборка карты вручную

### 3.1. Основа

1. Создайте пустой уровень, сохраните его в `/Game/Fishing/Maps/`.
2. В **World Settings → GameMode Override** укажите `/Game/XRFramework/Blueprints/BP_XRGameMode`.
3. Добавьте один `PlayerStart`: Location `(-700, -65, 300)`, Yaw `90`. Это положение tracking origin на уровне пола верхней палубы.
4. Добавьте пол верхней палубы с верхней поверхностью на `Z=300`; пол нижней палубы — на `Z=0`. Размеры задавайте в сантиметрах.
5. Добавьте **Fishing Scenario** (`AFishingScenario`) в `(0,0,0)` с Rotation `(0,0,0)`, Scale `(1,1,1)`. На карте должен быть один сценарий для одного игрока.
6. Для удобства редактирования можно сначала создать Blueprint-наследник `FishingScenario`, например `BP_FishingScenario`, и разместить его.

### 3.2. Точки сценария

В компонентах `FishingScenario` уже заданы стартовые положения. Для своей геометрии перенесите их на нужные места:

| Компонент | Относительная позиция по умолчанию, см | Назначение |
|---|---|---|
| `DeckPlayerPoint` | `(-700,-65,300)`, Yaw `90` | Игрок перед пультом на верхней палубе |
| `SortingPlayerPoint` | `(-60,0,0)`, Yaw `0` | Игрок перед сортировочной лентой |
| `ProcessingPlayerPoint` | `(240,-65,0)`, Yaw `90` | Игрок перед столом обработки |
| `ConveyorPath` | От `(0,-100,95)` до `(0,100,95)` | Путь подачи рыбы |
| `RecoveryPoint` | `(-10,0,95)` | Лоток пересортировки и возврата пропусков |
| `ProcessingSupplyPoint` | `(200,0,95)` | Следующая отсортированная рыба |
| `ProcessingPoint` | `(240,0,95)` | Положение рыбы на разделочном столе |
| `KnifeHome` | `(280,0,95)` | Исходное положение и возврат ножа |
| `FinishedPoint` | `(240,60,95)` | Положение принятого готового улова |
| `NetPosition` | `(-700,150,400)` | Точка крепления визуальной сети |

`ConveyorPath` — редактируемый Spline. Первой точкой задаётся начало, последней — конец подачи. Располагайте рыбу чуть выше поверхности ленты. Боковые приёмные лотки должны находиться вне пути движущегося улова.

Точки игрока обозначают положение пола под головой. При переходах код учитывает фактическое смещение HMD относительно tracking origin, поворачивает игрока к рабочему месту и использует короткое затемнение. Камера не качается вместе с тралом.

### 3.3. Станции

Добавьте акторы **Fishing Station** (`AFishingStation`). У каждого укажите **Scenario** — ссылку на размещённый `FishingScenario`, затем выберите **Kind**. Имена в таблице — значения enum; в Details Unreal может показывать их с пробелами.

| Станция | Kind | Позиция в тестовой карте, см | Yaw |
|---|---|---|---|
| Надеть защиту | `SafetyEquipment` | `(-780,-20,410)` | `90` |
| Аварийная остановка | `EmergencyStop` | `(-740,-20,410)` | `90` |
| Пуск / сброс остановки | `StartOrResume` | `(-660,-20,410)` | `90` |
| Рычаг лебёдки | `WinchLever` | `(-700,0,410)` | `90` |
| Переход в сортировочный цех | `GoToSorting` | `(-620,-20,410)` | `90` |
| Приёмник вида A | `SortingBin`, Species=`A` | `(-35,-55,95)` | `0` |
| Приёмник вида B | `SortingBin`, Species=`B` | `(-35,55,95)` | `0` |
| Переход к обработке | `GoToProcessing` | `(-60,65,110)` | `0` |
| Приёмник на столе | `ProcessingBoard` | `(240,0,95)` | `90` |
| Приёмник готовой рыбы | `DeliveryBin` | `(240,65,95)` | `90` |
| Повтор после результатов | `Restart` | `(300,-5,110)` | `90` |
| Информационное табло палубы | `StatusBoard` | `(-700,90,520)` | `-90` |
| Табло сортировки | `StatusBoard` | `(90,0,190)` | `180` |
| Табло обработки | `StatusBoard` | `(240,95,210)` | `-90` |

У станций:

- `Zone` задаёт область взаимодействия или приёма рыбы. По умолчанию её полуразмеры `(20,20,15)` см.
- `Mesh` — заменяемая модель; отдельный коллайдер приёмника уже существует в `Zone`. У кнопок модель должна изображать саму плашку: нажатие требует расстояния не более 8 см от её габаритов. Не назначайте кнопке модель всего пульта.
- `Handle` — рукоятка рычага: при захвате прикрепляется к контроллеру и следует за его положением и поворотом; при отпускании возвращается на станцию.
- `Label` — надпись. Разверните её лицом к игроку; для кнопок тестовой карты это Relative Yaw=`180`. У табло Relative Yaw=`0`, код устанавливает World Size=`5.5`. У рычага код поднимает надпись на локальный Z=`55`, устанавливает World Size=`4.5` и показывает состояние, скорость, шкалу и нагрузку. Длинные подписи кнопок разбиты на две строки.
- Для рычага локальная ось **+X** обозначает увеличение скорости. `LeverTravel=20` означает полный ход 20 см от положения руки в момент захвата. Перемещение вбок и вверх не меняет скорость. Рукоятка макета свободно следует за рукой; физического шарнира пока нет.

Лотки сортировки не должны перекрывать ленту, `RecoveryPoint`, друг друга или подающий лоток. Для приёма центр рыбы должен оказаться внутри `Zone`. `ProcessingBoard.Zone` разместите вокруг `ProcessingPoint`, `DeliveryBin.Zone` — вокруг `FinishedPoint`. Не перекрывайте разделочный стол приёмником готовой рыбы.

Переходы между рабочими местами выполняют кнопки сценария. NavMesh не требуется для этих переходов. Если нужен свободный телепорт средствами `BP_XRPawn`, отдельно добавьте `NavMeshBoundsVolume`, охватывающий доступные полы, и проверьте генерацию навигации.

### 3.4. Окружение

1. Добавьте геометрию пульта, ленты и разделочного стола с обычной блокирующей коллизией.
2. Сохраните верхнюю поверхность ленты и стола немного ниже центра рыбы; при стандартных точках подходит поверхность на `Z=90`.
3. Добавьте освещение.
4. Прикрепите модель трала к компоненту `NetPosition`. Во время выпуска точка опускается на 500 см, во время выборки возвращается в своё исходное положение.
5. Не добавляйте физическую симуляцию декоративной сети: её движение уже управляется сценарием.

## 4. VR-ввод и прохождение

`FishingScenario` при старте добавляет `FishingInteractionComponent` к игровому Pawn. Включённый по умолчанию `Attach VR Input` использует существующие:

- `MotionControllerLeftGrip` с Motion Source=`LeftGrip`;
- `MotionControllerRightGrip` с Motion Source=`RightGrip`;
- `IA_Grab_Left_Pressed`, `IA_Grab_Left_Released`, правые аналоги;
- `IA_Shoot_Left` и `IA_Shoot_Right` для дополнительного нажатия кнопок.

Новые Input Mapping Context создавать не требуется. Основной способ взаимодействия — **Grip рядом с предметом или кнопкой**, поэтому прохождение не зависит от наличия оружейного контекста для Trigger. Поднесите контроллер к самой плашке кнопки и один раз нажмите Grip или Trigger. Для кнопок дополнительно проверяется расстояние до габаритов `Mesh`: максимум 8 см, чтобы контроллер около рычага не нажимал соседний СТОП. Общий радиус поиска — 22 см от контроллера, фактический захват предмета ограничен расстоянием 40 см от его центра. Удерживаемые предметы освобождаются при потере tracking или VR-фокуса.

Табло показывает этап и одно следующее действие. Жёлтая надпись на кнопке обозначает следующий доступный шаг; выполненная экипировка зелёная, недоступные действия серые. СТОП подсвечивается жёлтым во время обязательной проверки, в остальное время он красный. У рычага зелёная надпись подтверждает захват, жёлтая предупреждает о нагрузке, красная показывает остановку с её причиной.

Порядок действий:

1. Поднесите руку к «НАДЕТЬ ЗАЩИТУ» и нажмите Grip или Trigger. После успеха надпись на кнопке станет «ЗАЩИТА НАДЕТА», а табло покажет следующий шаг. Экипировка пока меняет состояние сценария; модели и анимации переодевания нет.
2. Один раз нажмите «СТОП» для проверки безопасности, затем «НАЧАТЬ ЛОВЛЮ». На табло появится «ВЫПУСК ТРАЛА». Во время работы повторный пуск не нужен.
3. Зажмите Grip у рукоятки: она перейдёт в руку, появится зелёная надпись «РЫЧАГ В РУКЕ», скорость останется нулевой. Плавно сдвиньте руку вперёд примерно на 10 см и держите скорость около 50% по шкале. Первые 2 см не дают тяги; разгон ограничен 75 процентными пунктами в секунду. 10 см соответствуют установившейся скорости 50%, 20 см — 100%. При Yaw=`90` движение идёт вперёд по мировой +Y, локально это +X станции. Назад — немедленное снижение скорости. Отпускание Grip возвращает рукоятку на станцию и скорость в ноль без аварии.
4. Дождитесь «Трал выпущен: 100%» и отпустите Grip. Во время четырёхсекундного траления рычаг освобождается и временно заблокирован. После команды «ПОДЪЁМ ТРАЛА» снова зажмите Grip и сдвиньте руку вперёд до скорости около 50%. Дождитесь «Трал поднят: 100%».
5. После выборки нажмите «В ЦЕХ».
6. Берите рыбу с ленты и отпускайте над лотком A или B. Вытянутая модель обозначает A, плоская — B; подписи также показывают тип.
7. Пропущенная рыба окажется у `RecoveryPoint`. Неправильно распределённая рыба тоже возвращается туда и может быть исправлена. Ошибки учитываются один раз на рыбу.
8. После всей партии нажмите «К ОБРАБОТКЕ».
9. Переложите рыбу из подающего лотка в зону стола и отпустите.
10. Зажмите Grip рядом с рыбой свободной рукой: она останется на столе, а рука будет считаться придерживающей. Другой рукой возьмите нож.
11. Проведите `BladeTip` ножа последовательно через появляющиеся метки. У A — прямая траектория, у B — обход трёх сторон прямоугольника. Работа без придерживающей руки или той же рукой не засчитывается. Скачок кончика больше 40 см за кадр не засчитывается.
12. После сообщения о готовности отпустите придерживающую руку, возьмите рыбу повторно и положите в «ГОТОВЫЙ УЛОВ».
13. Появится следующая рыба из той же партии. После последней откроются результаты.
14. «НОВАЯ СМЕНА» очищает старые предметы и статистику, возвращает игрока на палубу и восстанавливает инструктаж.

Если нагрузка растёт, надпись у рычага становится жёлтой и просит сдвинуть его назад. При нагрузке выше 90% показывается обратный отсчёт; 1,5 с непрерывной перегрузки приводят к остановке. Причины различаются: «СТОП: НАЖАТА КНОПКА СТОП» и «СТОП: ПЕРЕГРУЗКА». При любой остановке отпустите Grip, нажмите **«СБРОС ОСТАНОВКИ»**, затем заново возьмите рычаг. После перегрузки используйте меньший ход. Обычное отпускание рычага даёт паузу; для её продолжения достаточно снова взять рукоятку.

Урон ножом и произвольное разрезание геометрии не моделируются. Нож и рыба, упавшие вне приёмников, возвращаются через 5 секунд; при падении ниже рабочей сцены — раньше.

### Подробный журнал событий

Категория **`LogFishing`** включена с подробностью `Verbose`. Откройте **Tools → Debug → Output Log** и в поиске укажите `LogFishing`. Те же записи сохраняются в `YakutSimulator/Saved/Logs/YakutSimulator.log`: стандартный префикс Unreal содержит время и номер кадра. Журнал позволяет сопоставить события нажатия, поиска цели, обработки станцией и изменения сценария.

События для кнопки защиты показаны ниже. Обработчики одного нажатия могут записываться в другом порядке в пределах одного кадра; сопоставляйте руку, действие, станцию и номер кадра:

```text
[Input.RawChanged] key=... value=1.000
[Input.Action] action=IA_Shoot_Left event=...Started...
[Interaction.Use] hand=Left stage=...Safety...
[Target.Query] ... radiusCm=22.0 overlaps=...
[Target.Candidate] ... kind=...SafetyEquipment reason=Eligible
[Target.Result] target=... reason=ClosestEligibleOverlap
[Station.Use] ... kind=...SafetyEquipment
[Safety.Equipped] previous=0 current=1 next=EmergencyStop
[Scenario.Feedback] ... message="Защита надета..."
[Station.Result] ... result=Accepted equipped=1
[Interaction.Result] ... result=Accepted
```

`Input.RawChanged` отражает изменение значений клавиш, связанных с действиями проекта. `Input.Action` отражает события Enhanced Input `Started`, `Completed` и `Canceled`. Для `Started` вычисленное `evaluatedValue` может быть нулевым по правилам Enhanced Input: проверяйте вместе с исходным `RawChanged`, состоянием действия и результатом взаимодействия. Trigger для нажатия станции обрабатывается один раз на начало нажатия; удержание не повторяет операцию каждый кадр. При Grip будет цепочка `Input.Action → Interaction.Grip → Station.Use`.

При отсутствии события проверяйте журнал в таком порядке:

| Запись | Что проверять |
|---|---|
| `Input.BindingMissing` | Не загрузился указанный Input Action |
| `Interaction.ReadinessChanged` | Игровой Pawn, Controller, EnhancedPlayerInput, привязанный Input Component, наличие рук, tracking и VR-фокус |
| `Snapshot.Action keys=[]` | В текущих активных назначениях нет клавиш для этого действия |
| `RawChanged` есть, `Input.Action` нет | Назначения, triggers, текущий input mode или потребление ввода другим обработчиком |
| `Target.Unavailable reason=MissingHand/MissingScenario` | Источники `LeftGrip`/`RightGrip` и ссылка на сценарий |
| `Target.Result reason=NoEligibleOverlap` | Нет подходящей станции рядом с рукой |
| `Target.NearestButton` | Имя ближайшей кнопки, расстояние до её центра, радиус поиска, размеры и состояние коллизии |
| `Target.Candidate reason=...` | Отсеивание чужого сценария, занятого/скрытого предмета или неподходящей станции |
| `Interaction.AutoRelease` | Потеря tracking, VR-фокуса, сценария или завершение смены |
| `Safety.EquipRejected reason=WrongStage` | Кнопка защиты доступна на этапе `Safety` |
| `Safety.Equipped previous=1` | Защита уже надета; следующий шаг — проверка СТОП и ПУСК |
| `Scenario.StartRejected` | Причина отказа запуска: защита, проверка СТОП или неподходящий этап |
| `HandTooFarFromButtonFace` | Поднесите контроллер к самой плашке кнопки: максимум 8 см от `Mesh`; одного попадания в широкую область `Zone` недостаточно |
| `Safety.EmergencyStop cause=StopButton` | Нажата кнопка СТОП; это не увеличивает счётчик перегрузок |
| `Safety.EmergencyStop cause=Overload` | Реальная перегрузка дольше 1,5 с; уменьшите ход рычага после сброса |
| `Cut.ReadinessChanged` | Нужна рыба на столе, её удержание второй рукой и нож в другой руке |

Станции — объекты сцены с зоной взаимодействия. Щелчок мышью по надписи сам по себе не вызывает `Station.Use`: симулятор должен передать нажатие контроллера, а его рука должна пересекать зону поиска. Расстояние `centerDistanceCm` измеряется до центра станции; при выборе цели учитывается пересечение сферы руки с коллизией зоны станции.

Каждые пять секунд при уровне `Verbose` записывается снимок состояния: этап, экипировка, проверка СТОП, позиции головы и обеих рук, tracking, текущий input mode, активные назначения и значения действий. Он помогает диагностировать случай, когда нажатия вообще не доходят до игрового компонента. Полные пути Input Actions и имена станций выводятся при инициализации. События захвата/отпускания предметов, рычага, подачи рыбы, сортировки, возврата, контрольных точек ножа, сдачи улова и переходов этапов также записываются в `LogFishing`.

В строке **Cmd** окна Output Log доступны:

```text
Fishing.DumpState
Log LogFishing Verbose
Log LogFishing Log
Log LogFishing Off
```

`Fishing.DumpState` немедленно выводит состояние всех игровых миров, даже если автоматическая диагностика выключена. `Verbose` включает подробный поиск целей и периодические снимки, `Log` оставляет события без периодических снимков, `Off` выключает категорию. Снимок отражает текущие значения; он не имитирует нажатия и не меняет состояние игры.

## 5. Настройка темпа и моделей

В `FishingScenario`:

| Параметр | По умолчанию | Что меняет |
|---|---:|---|
| `FishCount` | 8 | Размер партии; проверяется диапазон 2–32 |
| `DeploySeconds` | 8 | Время выпуска при полном ходе |
| `TrawlSeconds` | 4 | Ожидание между выпуском и подъёмом |
| `HaulSeconds` | 20 | Время подъёма при полном ходе |
| `ConveyorSpeed` | 12 см/с | Скорость рыбы вдоль Spline |
| `FeedInterval` | 3 с | Интервал подачи |
| `CutTolerance` | 3 см | Радиус приёма контрольной точки, диапазон 1–8 см |
| `FishClass` | `FishingItem` | Класс создаваемой рыбы |
| `KnifeClass` | `FishingItem` | Класс создаваемого ножа |

Для большой партии увеличьте площадь лотка пересортировки и проверьте досягаемость. Предметы по умолчанию имеют фиксированный размер, независимо от масштаба декоративного корабля.

Для своих ассетов создайте Blueprint-наследники `FishingItem`, замените `Mesh`, настройте `Body` и `BladeTip`, затем назначьте классы в сценарии. `Kind`, `Species` и принадлежность партии выставляются сценарием при создании. Для настоящих рыб скорректируйте траектории в `AFishingItem::GetCutPoints()`: сейчас это условные игровые операции для двух форм.

Для собственного интерфейса доступны `OnStageChanged`, `OnFeedback`, `Results` и `GetStatusText`. `NetDepth` и `WinchLoad` доступны для анимации барабана, звука и вибрации. Наличие аудио или UMG не является условием прохождения.

## 6. Проверка

Проверено 07.11.2026: сборки `YakutSimulatorEditor Win64 Development` и `YakutSimulator Win64 Development` успешны; все восемь тестов `Yakut.Fishing` проходят без ошибок и предупреждений. Полное прохождение сохранённой карты с восемью рыбами, остановкой, сбросом и повторным захватом перед подъёмом заняло 93,9 с. Актуальный отчёт: `YakutSimulator/Saved/FishingPrototype/controls-ui-results.json`; предыдущие отчёты захвата, журнала и прохождения: `lever-grab-results.json`, `diagnostics-results.json` и `playthrough-results.json` в той же папке. Сохранённая карта содержит 25 акторов прототипа и 14 правильно привязанных станций; позиции, направления, точки игрока и XR GameMode сверены с таблицами выше. Обычный запуск проекта открывает рыболовную карту, а Play создаёт `BP_XRPawn` с `FishingInteractionComponent`, Enhanced Input и источниками `LeftGrip` / `RightGrip`. Проверка шлема, удобства взаимодействий и упаковка дистрибутива остаются ручными шагами.

1. Сначала откройте карту и нажмите обычный Play: убедитесь в отсутствии ошибок создания классов и появления `FishingInteractionComponent` у Pawn. Без шлема ручное прохождение не предусмотрено.
2. В **Tools → Test Automation** найдите группу `Yakut.Fishing` и запустите:
   - `SafetyAndWinch` — обязательность инструктажа, границы скорости, остановка, перегрузка и полный цикл трала;
   - `LeverGrabAndFollow` — прикрепление рукоятки к контроллеру, движение и поворот вместе с рукой, сохранение размера, зелёное подтверждение, нейтраль при захвате и дрожании руки, плавный разгон, направление и пределы скорости, защита от второй руки, возврат при отпускании и исчезновении руки;
   - `ButtonTargetingAndStopRecovery` — повтор поз обеих рук из журнала сбоя: ввод около рычага не нажимает далёкий СТОП, намеренное нажатие работает, причина остановки не путается с перегрузкой, рукоятка освобождается, сброс возвращает нейтраль, табло последовательно ведёт через подготовку;
   - `InteractionDiagnostics` — причина отказа у недосягаемой кнопки, расстояние до ближайшей станции, журнал успеха и отказа, смена надписи и её сброс; ввод через Enhanced Input проверяет одно действие при удержании Trigger и новое действие после отпускания и повторного нажатия;
   - `SortingRecoveryAndOwnership` — неподанный или чужой предмет, ошибочный лоток, возврат пропуска, защита от двойного зачёта;
   - `CompleteShiftAndRestart` — обе процедуры обработки, необходимость второй руки, порядок точек, сдача всей партии, очистка при повторе;
   - `ReleaseThroughStations` — захват и отпускание над обоими лотками, перенос на разделочный стол и сдача обработанной рыбы через приёмник до завершения смены;
   - `SavedLevelPlaythrough` — запуск сохранённой карты в Play, проверка шести привязок Enhanced Input, кнопки и рычаг через `FishingInteractionComponent`, реальное движение ножа по кадрам, вся партия из восьми рыб, перегрузка и сброс, неверный лоток, пропуск, падение ножа, падение сырой и обработанной рыбы, сдача партии и повтор. Проверяются также высота пола и поправка на смещение головы при переходах.
3. В VR Preview проверьте оба контроллера, положение пола, досягаемость всех кнопок, лотков и ножа, правильность направления рычага и переходы между палубами.
4. Намеренно ошибитесь лотком, пропустите рыбу, уроните нож и вызовите перегрузку. После каждого случая смена должна оставаться проходимой.
5. Проверьте стабильную частоту кадров на целевом PCVR-комплекте. Прохождение автоматических тестов не проверяет удобство захвата и комфорт конкретного шлема.

## 7. Границы версии

Есть основной цикл смены, физические захваты, рабочие приёмники, упорядоченная обработка и восстановление обычных ошибок игрока. Сонар, заточка ножа, заморозка, обрыв троса и ремонт конвейера не включены. Визуальная сеть и операции обработки условные; сценарий ещё не является профессиональным тренажёром.
