# Как собрать новый сценарий клиники в Unreal Editor

По этой инструкции вы создадите свою карту, пациента, кейс, вопрос, инструментальный осмотр, исследование и статью справочника. Готовые Blueprint клиники обеспечивают захват приборов, смену поз, медкарту, книгу и разбор приёма. Для сборки сценария достаточно Unreal Editor.

Сквозной пример — `L_Clinic_Workshop`, один приём с жалобами на першение в горле и слабость. Игрок может спросить о кашле, измерить температуру и получить заключение по снимку. Числа и тексты здесь служат примером заполнения ассетов. Перед публикацией учебного приёма согласуйте медицинское содержание с профильным специалистом.

## 1. Подготовьте папки

Откройте `Content/Minigames/Clinic` в Content Browser. Для своих ассетов используйте подпапку `Workshop` внутри `Data/Indicators`, `Data/Actions/Questions`, `Data/Actions/Examinations`, `Data/Actions/Investigations`, `Data/Diseases`, `Data/Cases` и `Data/Patients`. Blueprint пациента положите в `Blueprints/Patients/Workshop`, карту — в `Content/Maps`. Готовый пример целиком можно посмотреть на `L_Clinic_Designer`.

Для создания любого `DA_*` в нужной папке нажмите **Add → Miscellaneous → Data Asset** и выберите класс `BP_Clinic…` из соответствующего шага. Для Blueprint используйте **Duplicate** у настроенного образца. Если Blueprint открылся в режиме Data Only, кнопка **Open Full Blueprint Editor** откроет **Components** и **Viewport**.

## 2. Определите показатели

Показатель — это вид сведений, например температура. В таблице задаётся его имя и тип, в кейсе — значение конкретного пациента.

1. Создайте **Add → Miscellaneous → Data Table**, выберите структуру строки **Clinic Indicator Row** и назовите таблицу `DT_ClinicWorkshopIndicators`.
2. Откройте её и добавьте строку `WorkshopCough`. Заполните **Display Name** — «Кашель», **Value Type** — `Choice`, **Categories** — `Present` и `Absent`. **Unit** оставьте пустым. Для нового числового показателя используйте `Number` и укажите единицу.
3. Для примера переиспользуйте строки `Temperature` и `ChestRadiograph` из общей `DT_ClinicIndicators`. При выборе показателя всегда задавайте и **Data Table**, и **Row Name**.

Один и тот же факт связывается по **таблице, строке и области**. Например, температура во рту — `DT_ClinicIndicators / Temperature / Mouth`. Для вопроса и заключения по снимку поле **Область** оставьте пустым (`None`).

## 3. Создайте действия игрока

Создайте три Data Asset класса `BP_ClinicActionDefinition`. У каждого заполните уникальный **Action Identifier**, видимый игроку **Display Name**, **Action Type** и **Открываемые показатели**.

| Ассет и ID | Тип и название в медкарте | Открываемый показатель |
| --- | --- | --- |
| `DA_Action_WorkshopAskCough`, `WorkshopAskCough` | `Question`, «У вас есть кашель?» | `DT_ClinicWorkshopIndicators / WorkshopCough` |
| `DA_Action_WorkshopMeasureTemperature`, `WorkshopMeasureTemperature` | `Examination`, «Измерить температуру» | `DT_ClinicIndicators / Temperature` |
| `DA_Action_WorkshopChestRadiograph`, `WorkshopChestRadiograph` | `Investigation`, «Рентгенография грудной клетки» | `DT_ClinicIndicators / ChestRadiograph` |

- **Вопрос.** Текст вопроса берётся из **Display Name**. Ответ задаётся в кейсе пациента.
- **Осмотр.** Включите **Требуется прибор**, задайте **Duration Seconds** = 2 и **Instruction** — «Поднесите термометр к подсвеченной зоне и удерживайте Trigger». В **Этапы обследования** добавьте один элемент с **Pose Identifier** = `Mouth` и одним элементом **Areas** = `Mouth`. Для осмотра без прибора снимите флажок. Если области нужны, добавьте их через этапы. Для результата без области оставьте этапы пустыми.
- **Исследование.** Задайте **Investigation Delay Seconds** = 5. Игрок назначает исследование кнопкой и получает готовый результат отдельным нажатием. Кабинет исследования и отдельный актор на карте для этого не требуются.

Если действие состоит из нескольких этапов, добавьте по записи на каждую позу и перечислите её зоны. Например, стетоскоп использует `ChestFront` с `LeftChest` и `RightChest`, затем `ChestBack` с `LeftBack` и `RightBack`. Значение в кейсе задаётся для каждой нужной пары «показатель + область».

## 4. Создайте диагноз и статью для книги

1. Создайте `DA_Disease_WorkshopViralInfection` класса `BP_ClinicDiseaseDefinition`. Укажите **Название** — «ОРВИ», затем заполните **Текст справочника** кратким описанием признаков и их ограничений. Поле **Источники** доступно в дополнительных свойствах.
2. В **Симптомы** добавьте строку. **Подпись в справочнике** — «Есть кашель», **Показатель** — `DT_ClinicWorkshopIndicators / WorkshopCough`, **Подходящие варианты** — `Present`, **Области** — пусто. Для числового симптома включите нужную границу, задайте число и укажите, входит ли граница в диапазон. Для показателя из осмотра укажите нужную область.
3. Возьмите существующий `DA_Disease_Pneumonia` как альтернативный вариант диагноза. Оба ассета добавите в каталог сценария в шаге 7.

Название болезни появится в списке диагнозов и в книге. Книга сверяет нажатый симптом со сведениями, которые игрок уже получил в текущем приёме. Свободный текст реплики сам по себе не создаёт показатель.

## 5. Настройте пациента и прибор

**Пациент.** Создайте `DA_Patient_Workshop` класса `BP_ClinicPatientProfile`, заполните **Имя**, **Возраст** и **Пол**. Сделайте копию подходящего пациента из `Blueprints/Patients`, назовите её `BP_ClinicPatient_Workshop` и назначьте `DA_Patient_Workshop` в **Class Defaults → Clinic → Patient → Карточка пациента**. Откройте **Clinic → Animation → Pose Definitions** и убедитесь, что там есть `Idle` и `Mouth`.

**Модель и анимации.** Чтобы сменить внешность, выберите **Components → Body** и назначьте Skeletal Mesh и совместимый Anim Class. На новом скелете создайте сокеты с именами областей из **Areas**. В стандартном наборе это `Mouth`, `LeftFinger`, `LeftChest`, `RightChest`, `LeftBack`, `RightBack`, `LeftForearm` и `LeftUpperArm`. В Blueprint выбирайте зоны в **Components** и настраивайте положение и **Shape → Box Extent** во Viewport и Details. Дочерние компоненты `*Highlight` задают видимые подсказки. В **Pose Definitions** для каждой позы назначьте **Loop Animation** и при необходимости **Transition Montage**. У всех пациентов сценария должны быть позы и области, используемые действиями его каталога. Подробная настройка AnimGraph и монтажей — в [инструкции по анимациям](ClinicPatientAnimationSetup.ru.md).

**Термометр.** Дублируйте `BP_ClinicThermometer` в `BP_ClinicThermometer_Workshop`. В **Class Defaults → Clinic → Action Definition** выберите `DA_Action_WorkshopMeasureTemperature`. При смене модели правьте **Components → Body**, для хвата — `GripPoint`, для точки контакта — `WorkingPoint`. Сохраните коллизию корпуса, пригодную для физического захвата. **Compile → Save** для изменённых Blueprint.

Для стандартных приборов можно взять готовые Blueprint и соответствующие им действия. Пульсоксиметр использует `MeasurePulseAndOxygen` и `LeftFinger`. Его **Finger Clip Duration Seconds** и **Finger Clip Contact Tolerance** находятся в **Class Defaults → Clinic**. Прибор крепится по Trigger и снимается по Grip после отсчёта. Новые модели и контактные осмотры собираются на основе готовых приборов. Новые способы взаимодействия требуют поддержки в коде.

## 6. Заполните кейс и правила разбора

Создайте `DA_Case_Workshop` класса `BP_ClinicPatientCaseDefinition`.

1. В **Приём** заполните **Жалобы** — «Першит горло, второй день чувствую слабость», **Начальная поза** — `Idle`, **Правильный диагноз** — `DA_Disease_WorkshopViralInfection`. Для первого кейса оставьте **Базовый набор** и **Известно с начала приёма** пустыми.
2. В **Данные кейса → Значения показателей** внесите три записи.

   | Таблица и строка | Область | Значение |
   | --- | --- | --- |
   | `DT_ClinicWorkshopIndicators / WorkshopCough` | Пусто | **Вариант** = `Present` |
   | `DT_ClinicIndicators / Temperature` | `Mouth` | **Число** = 37,3 |
   | `DT_ClinicIndicators / ChestRadiograph` | Пусто | **Вариант** = `Normal` |

3. В **Реплики** добавьте `DA_Action_WorkshopAskCough` с текстом «Да, со вчерашнего дня немного кашляю». В **Заключения и материалы** добавьте `DA_Action_WorkshopChestRadiograph` с текстом «Очаговых изменений не выявлено». При необходимости прикрепите звук или изображение. Для термометра достаточно числового значения.
4. В **Оценка → Достаточные наборы сведений** добавьте одну группу. В её **Все эти сведения** включите `WorkshopCough` без области и `Temperature` с областью `Mouth`. Эти два факта дают достаточные основания именно в примере. Если добавите другую группу, для оценки будет достаточно полностью собрать любую из групп. В **Разбор** поясните, какие сведения ожидались и как они связаны с выводом по кейсу. Поле **Необоснованные действия** можно использовать для конкретных действий с пояснением.

Сценарий предоставляет один каталог всем пациентам. Для каждого действия и каждой его области у каждого кейса укажите хотя бы один результат из списка: значение открываемого показателя, реплику, заключение или материал. Если добавили вопрос, уместно задать и отрицательные ответы для других пациентов. Все факты из групп оценки должны быть доступны через действия или **Известно с начала приёма**. Игрок может завершить обследование с неполными сведениями, а их достаточность учитывается при разборе.

Когда кейсов станет несколько, повторяющиеся значения и реплики можно вынести в `DA_ClinicCaseBaseline_Workshop` класса `BP_ClinicCaseBaseline` и назначить его каждому кейсу. Индивидуальные отличия задавайте в кейсе. Раздел **Итоговые показатели** с включённым **Show Clinic Baseline** показывает и унаследованные значения. Если переопределяете число, обновите связанный текст, когда в нём упоминается это число.

## 7. Соберите карту, подключите медкарту и книгу

1. **Подготовьте сценарий.** Дублируйте `BP_ClinicScenario` как `BP_ClinicScenario_Workshop`. В **Class Defaults → Clinic → Catalog** замените **Action Definitions** тремя действиями из шага 3, **Disease Definitions** — двумя болезнями из шага 4. Порядок в каталогах определяет порядок строк внутри группы действий, диагнозов и страниц книги. В **Clinic → Cases → Список приёмов** оставьте одну запись. В **Пациент** выберите класс `BP_ClinicPatient_Workshop`, в **Кейс** — `DA_Case_Workshop`. Установите **Initial Case Index** = 0. Нажмите **Compile → Save**.
2. **Подготовьте сцену.** Для пустой сцены создайте **File → New Level → Empty Level**, сохраните как `L_Clinic_Workshop` в `Content/Maps`. Добавьте пол с коллизией, свет, стол и `PlayerStart` на уровне пола лицом к рабочему месту. В **World Settings → Game Mode Override** используйте проектный GameMode по умолчанию или `BP_MainGameMode`. Если хотите использовать готовый кабинет, дублируйте `L_Clinic` в Content Browser. Откройте копию, запомните расстановку и удалите из неё старый экземпляр сценария, пациента и приборы. Существующую книгу подключите в шаге 5.
3. **Расставьте акторы.** Перетащите на карту `BP_ClinicScenario_Workshop`, `BP_ClinicPatient_Workshop` и `BP_ClinicThermometer_Workshop`. На карте должен быть один актор сценария. У него в **Details → Clinic → Equipment** через пипетку задайте **Место пациента** — размещённого пациента, **Instruments** — размещённый термометр. **Место пациента** определяет точку и направление появления пациентов из списка приёмов. Каждый прибор из **Instruments** должен ссылаться на действие из этого каталога, а каждому действию с флажком **Требуется прибор** нужен соответствующий прибор на карте.
4. **Расположите медкарту.** Выберите компонент `ConsoleDisplay` актора сценария и выставьте положение, поворот и масштаб у монитора. `BP_ClinicScenario_Workshop` уже содержит подключение `WBP_ClinicConsole`. Во время игры виджет возьмёт действия и диагнозы из каталога выбранного сценария. Для нового действия кнопка появится автоматически.
5. **Подключите книгу.** Если книги на карте ещё нет, перетащите `BP_ClinicReferenceBook` на стол. У экземпляра книги в **Details → Scenario** назначьте `BP_ClinicScenario_Workshop` с карты. Из каталога этого актора книга возьмёт список болезней и их порядок. Хват слева и зоны перелистывания справа настраиваются по [инструкции для книги](ClinicReferenceBookSetup.ru.md).
6. **Зарегистрируйте карту.** Откройте `Content/Base/Blueprints/BP_MainGameInstance` → **Class Defaults → Maps → Scenario Maps**. Добавьте запись с **Display Name** «Кабинет терапевта — учебный» и **Map** = `L_Clinic_Workshop`. Сохраните Blueprint и карту.

Чтобы добавить следующего пациента, создайте его карточку, Blueprint и кейс и добавьте пару в **Список приёмов**. Размещать на карте дополнительного пациента для каждой записи не нужно. Кнопка **Следующий пациент** станет доступна после выбора диагноза и разбора. После последней записи список начнётся заново.

## 8. Пройдите один приём

В VR Preview откройте свою карту из главного меню. Убедитесь, что видны имя и жалобы. Спросите о кашле и нажмите «Есть кашель» в книге. Измерьте температуру термометром. Назначьте снимок, дождитесь кнопки получения результата и нажмите её. Завершите обследование, выберите диагноз и прочитайте разбор. Если добавили второй кейс, перейдите к нему через **Следующий пациент** и убедитесь, что сведения предыдущего приёма очищены.

| Если возникла проблема | Где искать |
| --- | --- |
| Карты нет в меню | `BP_MainGameInstance → Scenario Maps`. Проверьте название, ссылку и сохранение записи |
| Приём не начался | Откройте **Output Log**. Проверьте место пациента, первый индекс, оба каталога и заполнение всех результатов и правил оценки |
| Кнопка отсутствует | Проверьте **Action Definitions** или **Disease Definitions** размещённого сценария |
| Прибор не измеряет | Сверьте **Action Definition**, **Instruments**, позу и область в действии. Дождитесь подсветки и проверьте **WorkingPoint** у прибора |
| Книга показывает чужой каталог или симптом не подтверждается | Проверьте **Scenario** у книги, затем совпадение таблицы, строки, области и значения полученного показателя |
