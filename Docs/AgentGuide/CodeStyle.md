# Код, типы и соглашения

Стиль исходников, имена, типы, обёртки, проверки и правила генерируемого кода; читать при изменении соответствующего кода.

Это обязательные инструкции проекта. Исходные даты, разрешения, исключения и границы выводов сохраняются. При пересечении систем прочитать все соответствующие документы.



### Исходный раздел: Рабочая область и сохранность изменений; строка 77

- Минимизировать diff. Не исправлять попутно несвязанные участки, не выполнять массовое переформатирование и не менять версии без необходимости. Читать окружающий код и соблюдать соглашения файла и модуля.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 94

## Стиль C++ и Unreal Engine



### Исходный раздел: Стиль C++ и Unreal Engine; строка 96

- PascalCase для функций, классов, типов, параметров и переменных с сохранением обязательных префиксов типов UE. Имена полные и описательные, без сокращений и однобуквенных имён.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 97

- Не добавлять к переменным Ptr, Ref, Reference, Handle и подобные обозначения типа или оболочки. Для булевых переменных разрешён и рекомендован префикс b.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 98

- Не использовать OnAuthority, Authoritative и аналогичные слова в именах функций.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 99

- Всегда использовать фигурные скобки для if, else и циклов, даже для одной строки. Не писать условия в одну строку, однострочные if и тернарные выражения.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 100

- Предпочитать GENERATED_BODY(). Не использовать GENERATED_UCLASS_BODY. Избегать namespace, кроме using namespace и необходимых случаев.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 101

- Использовать FString::Format вместо FString::Printf. Не использовать static_cast<void>(Value) для подавления неиспользуемого параметра.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 104

- Не растягивать формулы математическими локальными переменными, участвующими лишь в одной-двух простых операциях.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 105

- Ссылки на объекты сцены и мира в UPROPERTY объявлять через TObjectPtr или сырой указатель, не TWeakObjectPtr.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 107

- Категории переменных внутри EditInlineNew объектов не должны совпадать с категорией владеющего свойства или быть её дочерними категориями.


### Исходный раздел: Стиль C++ и Unreal Engine; строка 110

- Debug CVar обычно используют 0 = выключено, 1 = включено. Не переносить префикс SpaceDementia.Debug и другие имена чужих игр в новые системы проекта.
