## Сборка и проверка результата



### Исходный раздел: Сборка и проверка результата; строка 115

- Доминирующая конфигурация — Debug. Для editor target установленного UE использовать поддерживаемую DebugGame-конфигурацию, проверив реальные имена target; не копировать имена из соседних проектов.


### Исходный раздел: Сборка и проверка результата; строка 116

- После добавления новых .cpp выполнять сборку с -gather, если UBT использует Makefile-кеш: обычная сборка в этом UE может не обнаружить новый файл в существующем подкаталоге. Проверять присутствие нового исходника в действиях компиляции или unity-файле, не считать успешную сборку старого списка подтверждением нового кода.


### Исходный раздел: Сборка и проверка результата; строка 117

- Компиляция и проверки, необходимые для порученной задачи, разрешены без отдельной команды и подтверждения. Соблюдать последующие явные ограничения пользователя для конкретной задачи.


### Исходный раздел: Сборка и проверка результата; строка 118

- После изменения любого .cpp или .h перед дальнейшей работой с редактором, MCP и Blueprint закрыть редактор текущего проекта и его Live Coding Console с сохранением пользовательской работы, выполнить полную сборку фактического editor target и запустить редактор снова. Live Coding / Hot Reload не заменяют эту сборку, включая изменения UCLASS, UFUNCTION, UPROPERTY, делегатов и generated headers, если пользователь явно не запросил Hot Reload.


### Исходный раздел: Сборка и проверка результата; строка 119

- Если все .cpp собираются, но редактор не запускается, сообщить об этом и предложить отключить проблемные модули.


### Исходный раздел: Сборка и проверка результата; строка 120

- Начинать проверку с анализа кода, связанных путей выполнения, предоставленных логов и стеков, причин и граничных случаев. Затем выполнять соответствующие MCP-проверки. Недоступность MCP не подменяет предварительный анализ.


### Исходный раздел: Сборка и проверка результата; строка 122

- Отдельно фиксировать компиляцию, загрузку сохранённых ассетов, исполнение, PIE, multiplayer, cook и packaged runtime. Компиляция и искусственный test world не заменяют игровой сценарий. Сохранять неудачные результаты; пропуски, неполные и не соответствующие запросу прогоны не считать PASS.


### Исходный раздел: Циклическая доработка; строка 130

- Команда разрешает необходимые сборки, самостоятельный запуск и перезапуск редактора, PIE и динамические проверки через Unreal MCP в рамках проблемы без дополнительного разрешения. Выключенный редактор сам по себе не означает недоступность MCP: запустить редактор и дождаться подключения по правилам выше.


### Исходный раздел: Циклическая доработка; строка 131

- Сначала создать достоверный оракул: PASS означает решение заявленной проблемы, FAIL — её наличие. Допустимы MCP-проверки состояния, логов, console, PIE, Automation и Functional Tests. Осмотр исходников сам по себе оракулом не является.


### Исходный раздел: Циклическая доработка; строка 132

- Повторять: оракул-тест, исправление, необходимая сборка, перезагрузка на новый binary, прогон через MCP. Для игрового сценария выполнять StopPIE / StartPIE и необходимый прогрев. Если оракул неверно выражает проблему, исправить его и продолжить.


### Исходный раздел: Циклическая доработка; строка 134

- Останавливаться только после PASS или при отсутствии необходимой MCP-возможности, подтверждённом через list_toolsets / describe_toolset либо после запуска редактора и положенного ожидания подключения. Сообщить конкретный блокер и последние свидетельства FAIL. Длительность, число итераций, стоимость и сложность сами по себе не являются причиной остановки.


### Исходный раздел: Циклическая доработка; строка 135

- После PASS или допустимой остановки завершить PIE, закрыть редактор текущего проекта и его Live Coding Console, восстановить временную конфигурацию и удалить только посторонние временные скрипты и анализаторы, созданные для цикла. Сохранить исправление, постоянные тесты, резервные копии и свидетельства проверки. Не удалять проектные данные и кеши; не затрагивать редакторы других проектов.



### Исходный раздел: Полная проверка; строка 142

- По каждому найденному тесту сообщить имя, вид, карту и runtime-конфигурацию, PASS / FAIL / BLOCKED, длительность при наличии и конкретные свидетельства MCP/лога. Указать итоговые количества и пробелы обнаружения или покрытия; не заменять список необъяснённой общей цифрой.


### Исходный раздел: Полная проверка; строка 143

- После прогона остановить PIE, закрыть редактор проекта и его Live Coding Console, восстановить временные настройки. Сохранить постоянные тесты и результаты; удалить только посторонние временные файлы этого прогона.
