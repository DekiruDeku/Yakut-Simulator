# Настройка мини-игр и сборка рыболовного уровня

Актуальная карта: `/Game/MiniGames/Fishing/Maps/L_Fishing`. Открывайте её через Content Browser или обычным запуском проекта. Launcher использует стартовую карту из Project Settings → Maps & Modes. Для проверенного здесь Meta XR Simulator используется `Start-YakutSimulator.ps1 -Simulator`; для шлема — запуск без этого ключа.

Собранная Windows-версия находится в `YakutSimulator/Saved/Packaged/MiniGames/Windows`. Для неё есть запуск `Start-YakutSimulator.ps1 -Packaged`; для симулятора — `Start-YakutSimulator.ps1 -Simulator -Packaged`. Сначала закройте редактор/другую игровую сессию. Режим симулятора использует локальный runtime 69 и отключает предварительное кеширование PSO только в дочернем процессе собранной игры: на этой машине оно вызывало ошибки D3D12 при спекулятивном создании PSO. Обычный запуск с шлемом сохраняет проектные настройки. На первом появлении материала в режиме симулятора возможна задержка создания PSO.

## Что где редактировать

| Задача | Ассет или объект |
|---|---|
| Размер партии, цикл видов, скорости, нагрузка, допуски, очки, сообщения | `/Game/MiniGames/Fishing/Data/DA_Fishing_Default` |
| Порядок заданий и переходы | `/Game/MiniGames/Fishing/Flow/ST_Fishing_Default` |
| Название вида и класс рыбы | `DA_Fish_A`, `DA_Fish_B` в той же папке Data |
| Модель, материалы, коллизия, захват, путь обработки рыбы | `BP_Fish_A`, `BP_Fish_B` в `MiniGames/Fishing/Blueprints` |
| Модель и рабочая точка ножа | `BP_Knife` в той же папке |
| Кнопка, рычаг, приёмник, табло | `BP_InteractionButton`, `BP_InteractionLever`, `BP_ItemReceiver`, `BP_StatusPanel` в `Common/Blueprints` |
| Вид интерфейса, шрифты, размеры, расположение полей | `/Game/Common/UI/WBP_MiniGamePanel` |
| Цвета, форматы подписей/обратной связи и частота обновления UI | `/Game/Common/Data/DA_DefaultUIStyle` |
| Действия ввода, Mapping Context, досягаемость, диагностика | `/Game/Common/Data/DA_XRInteraction` |

| Точки появления, рабочие места, лента, ссылки на станции | Актор `Fishing Scenario` в уровне |

Примитивы Unreal назначены в Blueprint как временные модели. Runtime-код не подставляет их вместо отсутствующего контента. Меняйте меш и материалы в Blueprint; запуск и повтор смены сохраняют эти настройки. Декорации размещаются обычными акторами уровня.

Профиль содержит настройки, а не прогресс. В начале смены создаётся отдельная копия его значений. После правки параметров в PIE перезапустите смену или Play, чтобы применить изменения. На время прохождения созданные рыбы, инструмент, счётчики и таймеры принадлежат конкретному сценарию и его RunId.

## Собрать уровень с нуля

1. Создайте уровень в собственной папке Content. Для доработки готовой сцены используйте Save Current Level As и работайте с копией `L_Fishing`.
2. В World Settings → GameMode Override назначьте `BP_MiniGameGameMode`. Добавьте PlayerStart, поверхность палубы и рабочие помещения. Сохраните уровень.
3. Перетащите C++-актор `FishingMiniGameScenario` в уровень. Укажите Definition = `DA_Fishing_Default` либо его дубликат. Оставьте Auto Start включённым для автоматического начала смены.
4. Выберите его `ConveyorPath`. Добавьте минимум две точки сплайна вдоль ленты. Путь задаёт положение и направление рыбы; движение использует расстояние в сантиметрах. Декоративную ленту размещайте отдельно.
5. Разместите компоненты-ссылки: `RecoveryPoint` — лоток пересортировки; `ProcessingSupplyPoint` — подача на обработку; `ProcessingPoint` — центр рабочей доски; `KnifeHome` — подставка ножа; `FinishedPoint` — место принятого продукта. Точки должны находиться над поверхностями и вне геометрии стола.
6. Расположите `DeckPlayerPoint`, `SortingPlayerPoint`, `ProcessingPlayerPoint` **на уровне пола**. Yaw задаёт направление взгляда. Перемещение учитывает горизонтальное смещение шлема относительно Pawn и не переносит высоту глаз в координату пола.
7. В `Workplaces` добавьте `Deck`, `Sorting`, `Processing` и назначьте соответствующие компоненты. Имена совпадают с `Workplace` в заданиях профиля. Можно добавить свои рабочие места и использовать их в новых заданиях.
8. Расположите `NetPosition` в положении поднятой сети. Прикрепите к этому компоненту актор с нужным Static/Skeletal Mesh сети. Механика двигает компонент на `Winch.LoweredOffset × Depth`. Геометрия и материалы сети остаются назначенными дизайнером.
9. Назначьте меш компонента `CutGuide` — это маркер следующей точки обработки. Его масштаб и материалы задаются здесь. При работе меняются только положение и видимость маркера.
10. Разместите `BP_InteractionLever`. Укажите у актора Scenario = ваш сценарий. В компоненте Lever назначьте Action Id = `Winch`. В `Fishing Scenario.WinchStation` укажите этот актор.
11. Разместите шесть `BP_InteractionButton`: защита, СТОП, пуск/сброс, переход в цех, переход к обработке, новая смена. У всех назначьте Scenario. В компоненте Button задайте соответственно Action Id: `Equip`, `Stop`, `Start`, `GoSorting`, `GoProcessing`, `Restart`. При собственных именах измените и соответствующие Actions в профиле.
12. Разместите по одному `BP_ItemReceiver` на каждый уникальный вид рыбы. Укажите Scenario. Добавьте станции и определения видов в `Fishing Scenario.SortingBins`. Определение вида должно быть **тем же ассетом**, который используется в Species Cycle.
13. Добавьте ещё два `BP_ItemReceiver`: доску обработки и лоток сдачи. Укажите их в `ProcessingStation` и `DeliveryStation`. Receiver Id для стандартных подписей: `Board` и `Delivery`.
14. Добавьте `BP_StatusPanel` для задач. Назначьте Scenario. Для дополнительного табло лебёдки назначьте Display.Panel Id = `Winch` (значение из Winch Panel профиля). Табло можно добавить в состав декорированного пульта.
15. Для каждого Widget Component настройте собственные Draw Size, относительные положение/поворот/масштаб. Его лицевая сторона должна смотреть на игрока. Задайте Widget Class, если нужен отдельный вид панели; без него используется Panel Class из стиля.
16. Сохраните Blueprint и уровень. В Content Browser выполните Validate Assets для профиля и определений видов. Запустите Play: ошибки привязок выводятся в Output Log с префиксом `[Configuration.Invalid]`; смена с некорректными настройками не запускается.
17. Выполните полную смену. После декорирования повторите проверку досягаемости рук, зон кнопок, лотков и рабочей точки ножа. Области взаимодействий должны совпадать с понятными игроку функциональными местами.

На готовой `L_Fishing` все эти связи уже назначены. `MiniGame.CreateExampleContent` создаёт недостающие примеры ассетов. Он не нужен при обычном запуске и не создаёт/перезаписывает уровни. Одноразовый перенос исходной карты завершён; его исходник сохранён в архиве миграции.

## Заменить геометрию

**Рыба.** Создайте дочерний Blueprint от `FishingFish` либо дубликат имеющегося. Назначьте Mesh и материалы, настройте визуальный transform. Отдельно задайте `Body.Box Extent` и положение `Grab`: коллизия не должна автоматически охватывать весь декоративный меш. Для Skeletal Mesh можно добавить свой компонент и оставить штатный Mesh пустым; нужен хотя бы один видимый mesh-компонент.

`CutPath` содержит контрольные точки в пространстве рыбы. Ставьте их над поверхностью модели в порядке обработки. Нужно минимум две точки. Они могут образовывать прямую, дугу или несколько последовательных участков. Допуск задаётся в профиле. Масштаб модели и transform самого сплайна учитываются при обработке.

Событие Blueprint `OnWorkStateChanged` позволяет назначить вид обработанной рыбы, проиграть анимацию или эффект. Все ссылки на альтернативные меши, материалы и эффекты храните в переменных этого Blueprint. Нативная механика не выбирает внешний вид по номеру вида.

**Нож.** В `BP_Knife` замените Mesh, настройте Body, точку захвата, Snap To Hand и `ToolTip` на кончике лезвия. Контроль обработки использует ToolTip, а не origin меша. Траектория проверяется по последовательным положениям этой точки. Скачки больше Max Knife Step не засчитываются.

`ToolTipVisual` — отдельный меш рабочей точки инструмента. Его меш, материал и размер задаются в Blueprint; во время захвата компонент виден, после отпускания скрывается. В тестовом ноже это голубая сфера на кончике. Компонент не участвует в коллизии и не меняет положение самого `ToolTip`.

`BraceIndicator` у рыбы — меш подтверждения придерживания на доске. В примерах это зелёная сфера рядом с рыбой. Она видна только когда рыба загружена на доску, захвачена рукой и рука находится в пределах `Processing.BraceDistance`. При отпускании или отдалении руки подтверждение исчезает. Меш, материал, положение и размер настраиваются в Blueprint рыбы. `CutGuide` сценария показывает следующую точку разреза; на тестовой карте ей назначен жёлтый материал. Все три маркера можно заменить дизайнерскими мешами и материалами.

На этапе разделки основная шкала показывает **текущую рыбу**: принятые контрольные точки / все точки её `CutPath`. Вторая шкала показывает долю сданной партии. Поэтому первая шкала изменяется уже после первой принятой метки, а не после завершения целой рыбы. Живые подписи показывают, какая рука удерживает рыбу и нож. При готовности ножа выводятся номер следующей метки, расстояние от `ToolTip` до неё и допустимое расстояние `CutTolerance`.

Заголовок подсказывает причину отсутствия прогресса: сначала положить и отпустить рыбу на доске; зажать Grip у рыбы; вернуть придерживающую руку ближе; взять нож другой рукой; подвести кончик к следующей метке; двигать нож плавнее после скачка больше `MaxKnifeStep`. После завершения разреза нужно отпустить придерживающую руку, взять готовую рыбу повторно и отпустить над приёмником готового улова. Тексты и форматы находятся в `DA_Fishing_Default.Messages`, ключи `Processing*`, `CurrentFishCut`, `FishBraced`, `ItemHeld`, `LeftHand`, `RightHand`. Время показа предупреждения о скачке задаётся `Processing.StrokeWarningSeconds`.

В Meta XR Simulator 1.69 для разделки выбирайте в `Inputs → Active Inputs` один контроллер за раз (`[` / `]`). `U` — удерживаемый Grip; двойное нажатие колёсика — `Grip Button (Sticky)`, который позволяет оставить захват первой руки включённым и перейти ко второй. Сначала перенесите рыбу на доску и отпустите; затем снова захватите её для придерживания. Дождитесь зелёного подтверждения и подписи руки, затем переключитесь на вторую руку и возьмите нож. Совмещайте голубой кончик с жёлтыми метками по порядку. Если рыба не зафиксирована, следуйте конкретной подсказке табло.

**Рычаг.** Mesh — основание, Handle — движущаяся рукоятка. Поле Lever.Handle ссылается на перемещаемый компонент. `LocalAxis`, `Travel`, `DeadZone`, `Acceleration` задают направление, полный ход, нейтраль и разгон. При захвате рукоятка прикрепляется к контроллеру; положение захвата становится нулём. После отпускания восстанавливается её исходный transform. Вместо штатного Handle можно указать другой Scene Component.

**Кнопка.** `PressZone` определяет физическую область нажатия, Button.Max Hand Distance — небольшой допуск вокруг неё. Увеличение меша всего пульта не увеличивает область СТОП. Не объединяйте соседние кнопки одним большим PressZone. Переносите визуал, PressZone и подпись согласованно.

**Лоток.** `Zone` — объём приёма. Рыба принимается при отпускании, если её origin находится внутри объёма. Слишком маленькая зона или поверхность, пересекающая область отпускания, затрудняет попадание. Лоток не принимает удерживаемую рыбу, предмет другого сценария или прошлой смены.

Пустая презентация (нет заголовка, текста и метрик) скрывает общий виджет. Например, табло рычага появляется только во время выпуска/подъёма; инструктаж остаётся на основном табло. В собственном Widget Blueprint можно дополнить представление через OnPresentationChanged.

## Изменить задания

1. Дублируйте `DA_Fishing_Default` и `ST_Fishing_Default`. Назначьте дубликат дерева в Flow нового профиля и этот профиль актору уровня.
2. В профиле запись `Objectives` задаёт Id, Title, Instruction, Operation, Workplace, Allowed Actions, Completion Event и Final. Положение записи в массиве само по себе не меняет переходы уже созданного StateTree.
3. В StateTree у каждого состояния есть задача **Mini-game objective** с тем же Objective Id. При входе она активирует описание, рабочее место и выбранную операцию. Переход `On Event` должен слушать Completion Event соответствующей записи.
4. Для промежуточного задания добавьте запись Objectives и состояние с этой задачей. Вставьте переходы через него. Для простого подтверждения можно добавить Action Events: действие → Gameplay Tag и разрешить действие в Allowed Actions.
5. Для автоматической паузы у задачи есть Auto Complete Seconds; добавьте переход `On State Succeeded`. Для нестандартного условия используйте обычные задачи/условия StateTree или Blueprint.
6. Для пропуска проверки СТОП измените переход с Equip сразу на Start и выключите Require Stop Test. Для пропуска экипировки аналогично меняются дерево и Require Equipment. Флаги сами не редактируют граф переходов.
7. Операция определяет включаемую механику: Safety, Deploy, Trawl, Haul, Sorting, Processing, Results. Задание с пустой Operation служит ожиданием/инструкцией. Не запускайте обработку до появления отсортированного улова.
8. Итоговая запись имеет Final = true. Её состояние завершает общий запуск; Restart разрешён после завершения или прерывания. Скомпилируйте StateTree и проверьте профиль.

Id заданий, действий и рабочих мест — стабильные FName. События переходов — Gameplay Tags; собственные добавляются в Project Settings → Gameplay Tags. Тексты игрока — FText из профиля. `Messages` содержит также шаблон Results с именованными полями Score, Sorted, Processed, Delivered, Mistakes, Missed, Overloads, Seconds.

## Добавить вид и другой пресет

1. Создайте Blueprint рыбы с собственными мешем и CutPath.
2. Создайте Data Asset класса `FishSpeciesDefinition`, задайте уникальный Id, Display Name, Actor Class.
3. Добавьте ассет в Species Cycle профиля. Порядок цикла задаёт состав партии; один вид может повторяться в цикле.
4. Разместите его лоток и добавьте соответствие в Sorting Bins. Править enum или C++ для нового вида не требуется.
5. Дублируйте профиль, задайте уникальный Id и измените Catch, Winch, Processing, Scoring, Messages. Назначьте его сценарию. Для изменения последовательности также используйте отдельный StateTree.

В `/Game/Tests/MiniGames` находятся независимый общий сценарий и альтернативный пресет рыбалки с тремя видами. Эти ассеты предназначены для тестов и не входят в обычную упаковку игры. Для использования трёх видов на собственной карте добавьте третий лоток.

## Порядок действий игрока

1. Поднести контроллер к «Надеть защиту», один раз нажать Grip или Trigger.
2. Один раз нажать СТОП для проверки, затем «Начать ловлю».
3. Удерживая Grip у рукоятки, плавно подать руку вперёд примерно до 50%. Рукоятка находится в руке, скорость и нагрузка видны на табло. Отпустить Grip для паузы.
4. После выпуска отпустить рукоятку. Дождаться команды подъёма, снова взять рычаг и поднять трал.
5. При предупреждении нагрузки вернуть руку назад. После остановки отпустить Grip, нажать «Сброс остановки» и снова взять рычаг из нейтрали.
6. Нажать «В цех». Брать рыбу с ленты и отпускать в лоток её вида. Ошибочная или пропущенная рыба возвращается для повторной сортировки.
7. Нажать «К обработке». Перенести поданную рыбу на доску. Одной рукой придерживать её, другой взять нож и провести его кончиком по контрольным точкам по порядку.
8. Отпустить рыбу, взять готовую и перенести в лоток сдачи. Повторить до конца партии. Нажать «Новая смена» для повтора.

## Диагностика и проверка

`MiniGame.DumpState` выводит запуск, задачу, руки и удерживаемые компоненты. `Fishing.DumpState` добавляет состояние лебёдки, улова и обработки. Категории: `LogMiniGame`, `LogInteraction`, `LogFishing`; подробный уровень включается через `log LogInteraction Verbose` и `log LogFishing Verbose`.

В журнале есть события ввода, кандидаты целей, расстояния/отказы, результат кнопки, захват/отпускание, автоматическое освобождение, события StateTree, сортировка, контрольные точки обработки и восстановление предметов. Настройки Diagnostic Interval и Raw Input Log Threshold находятся в профиле ввода. Повторяющиеся сырые значения не печатаются каждый кадр.

В Session Frontend → Automation выбирайте `Yakut.MiniGames`. Перед SavedLevelPlaythrough сохраните карту и остановите Play. Тест прохождения использует синтетические положения рук и обычные тики уровня. Реальные контроллеры, комфорт, читаемость и производительность проверяются отдельно на целевом шлеме.

Для новой мини-игры используйте общий MiniGameScenario, профиль, StateTree, Pawn и компоненты взаимодействия. Специальные правила реализуются в её собственном наследнике/компонентах через ExecuteAction, TryReceive, RecoverItem и события задач. Общие классы не содержат ссылок на рыбалку. Педиатрия в этой версии не реализована.
